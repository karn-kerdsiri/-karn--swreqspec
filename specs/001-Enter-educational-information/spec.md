# Feature: กรอกข้อมูลผลการศึกษา (Academic Record Entry)
Spec ID: SPEC-EDU-001 | Source: Use Case Specification UC-01 กรอกข้อมูลผลการศึกษา | Use case: UC-01
Owner: ทีม B | Status: Draft v2 | Updated: 2569-09-19

## Goal
นักศึกษาที่เข้าสู่ระบบแล้ว กรอกข้อมูลผลการศึกษาและแนบเอกสาร Transcript แล้วส่งข้อมูลได้สำเร็จภายใน 5 นาที
โดยระบบบันทึกข้อมูล ตั้งสถานะเป็น "รอตรวจสอบคุณสมบัติ" และแจ้งผลกลับทางอีเมลและการแจ้งเตือนในระบบ

## Scope
### In scope
- IN-EDU-01 แสดงแบบฟอร์มผลการศึกษา พร้อมทำเครื่องหมายฟิลด์บังคับทุกฟิลด์          <- UC-01 ขั้น 1-2
- IN-EDU-02 กรอกและแก้ไขข้อมูลผลการศึกษาของรอบที่เปิดรับ ก่อนกดส่ง               <- UC-01 ขั้น 3, 5
- IN-EDU-03 บังคับแนบเอกสาร Transcript อย่างน้อย 1 ไฟล์ พร้อมตรวจชนิดและขนาดไฟล์  <- UC-01 ขั้น 4
- IN-EDU-04 ตรวจความครบถ้วนและรูปแบบข้อมูลก่อนบันทึก                          <- UC-01 ขั้น 7, alt 1-2
- IN-EDU-05 บันทึกข้อมูล ตั้งสถานะ และแสดงข้อความยืนยันบนหน้าจอ                 <- UC-01 ขั้น 8-9
- IN-EDU-06 แจ้งเตือนผลการบันทึกทางอีเมลและการแจ้งเตือนในระบบ                   <- UC-01 Description
### Out of scope
- OUT-EDU-01 การตรวจสอบคุณสมบัติและอนุมัติผล (ทำหลัง UC-01 โดย use case อื่น)
- OUT-EDU-02 การเข้าสู่ระบบและยืนยันตัวตน - ถือว่าสำเร็จแล้ว (precondition ของ UC-01)
- OUT-EDU-03 การเปิด/ปิดรอบแบบฟอร์มโดยเจ้าหน้าที่ - ถือว่ามีข้อมูลรอบอยู่แล้ว
- OUT-EDU-04 การดึงผลการศึกษาอัตโนมัติจากระบบทะเบียน - UC-01 ระบุว่านักศึกษากรอกเอง
- OUT-EDU-05 การตรวจความถูกต้องของเนื้อหาใน Transcript (OCR/เทียบกับสถาบัน) - ระบบตรวจแค่ชนิดและขนาดไฟล์

## Constraints
- IF-AUTH-01 ทุก request ของฟีเจอร์นี้ต้องมี session ที่ยืนยันตัวตนแล้ว มิฉะนั้นตอบ HTTP 401
- IF-FORM-01 ระบบต้องอ่านสถานะรอบแบบฟอร์ม (open/closed) จากข้อมูลตั้งค่ารอบ ก่อนแสดงและก่อนบันทึกทุกครั้ง
- IF-FILE-01 ไฟล์แนบเก็บใน Supabase Storage และตารางข้อมูลผลการศึกษาอ้างอิงด้วย bucket + storage path เท่านั้น
- IF-FILE-02 bucket ของ Transcript ต้องเป็น private และเข้าถึงผ่าน signed URL อายุไม่เกิน 15 นาที
- IF-MAIL-01 ส่งอีเมลแจ้งเตือนแบบ asynchronous ผ่านคิว การบันทึกต้องไม่รอผลการส่งอีเมล
- DOM-PDPA-01 บันทึก audit log ทุกครั้งที่สร้าง แก้ไข หรือเปิดดูข้อมูลผลการศึกษา
- DOM-PDPA-02 audit log ต้องมี ผู้กระทำ เวลา รหัสนักศึกษา และชนิดการกระทำ เก็บไม่น้อยกว่า 1 ปี
- CON-DATA-01 ข้อมูลผลการศึกษา 1 ชุดต่อนักศึกษา 1 คนต่อ 1 รอบ (unique: student_id + round_id)

## Data Rules
- DR-EDU-01 ฟิลด์บังคับ: ระดับการศึกษา, ชื่อสถาบัน, สาขาวิชา, ปีการศึกษา, ภาคเรียน, GPAX, หน่วยกิตสะสม
- DR-EDU-02 GPAX ต้องเป็นตัวเลข 0.00-4.00 ทศนิยมไม่เกิน 2 ตำแหน่ง นอกช่วงนี้ถือว่ารูปแบบไม่ถูกต้อง
- DR-EDU-03 หน่วยกิตสะสมต้องเป็นจำนวนเต็ม 0-999 ค่าติดลบหรือมีทศนิยมถือว่ารูปแบบไม่ถูกต้อง
- DR-EDU-04 ปีการศึกษาเป็นเลข 4 หลัก (พ.ศ.) และต้องไม่มากกว่าปีการศึกษาปัจจุบัน
- DR-EDU-05 ภาคเรียนรับค่า 1, 2 หรือ 3 (ภาคฤดูร้อน) เท่านั้น
- DR-EDU-06 ไฟล์แนบรับเฉพาะ .pdf .jpg .png ขนาดไม่เกิน 5 MB ต่อไฟล์ และไม่เกิน 5 ไฟล์ต่อการส่ง 1 ครั้ง
- DR-EDU-07 ต้องมีไฟล์แนบชนิด Transcript อย่างน้อย 1 ไฟล์ จึงจะส่งข้อมูลได้ (ไฟล์อื่นเป็นตัวเลือกเสริม)

## Requirements
- FR-EDU-01 ระบบต้องแสดงแบบฟอร์มพร้อมฟิลด์ตาม DR-EDU-01 และทำเครื่องหมาย * ที่ฟิลด์บังคับทุกฟิลด์ รวมช่องแนบ Transcript
- FR-EDU-02 เมื่อรอบแบบฟอร์มมีสถานะ closed ระบบต้องแสดงฟอร์มแบบอ่านอย่างเดียว และปฏิเสธการบันทึกด้วย HTTP 409
- FR-EDU-03 ระบบต้องรับไฟล์แนบตาม DR-EDU-06 และปฏิเสธไฟล์ที่ผิดเงื่อนไขโดยไม่ล้างข้อมูลที่กรอกไว้
- FR-EDU-04 ระบบต้องแสดงหน้าสรุปข้อมูลและรายชื่อไฟล์แนบให้ตรวจสอบ ก่อนยืนยันส่ง       <- UC-01 ขั้น 5
- FR-EDU-05 เมื่อกรอกไม่ครบ ระบบต้องไม่บันทึก และแสดงข้อความชี้เฉพาะทุกช่องที่ยังว่าง     <- UC-01 alt 1
- FR-EDU-06 เมื่อรูปแบบข้อมูลไม่ถูกต้องตาม DR-EDU-02 ถึง DR-EDU-05 ระบบต้องไม่บันทึก และแจ้งช่องที่ผิดพร้อมรูปแบบที่ถูกต้อง   <- UC-01 alt 2
- FR-EDU-07 เมื่อเอกสารไม่ตรงเงื่อนไขตาม DR-EDU-06 ระบบต้องแจ้งเหตุผลและให้อัปโหลดใหม่เฉพาะไฟล์นั้น   <- UC-01 alt 3
- FR-EDU-08 เมื่อผ่านการตรวจทั้งหมด ระบบต้องบันทึกข้อมูล ตั้งสถานะเป็น "รอตรวจสอบคุณสมบัติ" และแสดงข้อความยืนยันพร้อมวันเวลาที่บันทึก   <- UC-01 ขั้น 7-9
- FR-EDU-09 เมื่อบันทึกสำเร็จ ระบบต้องสร้างการแจ้งเตือนในระบบ และส่งคำขอส่งอีเมลเข้าคิวภายในธุรกรรมเดียวกัน   <- UC-01 Description
- FR-EDU-10 หากส่งอีเมลไม่สำเร็จ ระบบต้องคงข้อมูลที่บันทึกไว้ และนำอีเมลเข้าคิวส่งซ้ำ
- FR-EDU-11 หากบันทึกลงฐานข้อมูลไม่สำเร็จ ระบบต้อง rollback ทั้งชุด ไม่สร้างข้อมูลบางส่วน และแสดงรหัสข้อผิดพลาดพร้อมปุ่ม "ลองใหม่"   <- UC-01 exception
- FR-EDU-12 เมื่อมีข้อมูลของรอบนั้นอยู่แล้ว ระบบต้องแสดงข้อมูลเดิมในฟอร์ม และการส่งซ้ำเป็นการแก้ไขข้อมูลเดิมตาม CON-DATA-01
- FR-EDU-13 เมื่อไม่มีไฟล์ Transcript ตาม DR-EDU-07 ระบบต้องไม่บันทึก และแจ้งว่าต้องแนบ Transcript ก่อนส่ง
- FR-EDU-14 หากอัปโหลดไฟล์ขึ้น Supabase Storage สำเร็จแต่บันทึกฐานข้อมูลไม่สำเร็จ ระบบต้องลบไฟล์ที่เพิ่งอัปโหลดทิ้ง

## Quality Requirements
- NFR-PERF-01 บันทึกข้อมูลผลการศึกษา: เวลาตอบสนอง p95 <= 2 วินาที ที่ผู้ใช้พร้อมกัน 300 คน
- NFR-PERF-02 อัปโหลดไฟล์ขนาด 5 MB เสร็จภายใน 10 วินาที ที่แบนด์วิดท์ขาขึ้น 10 Mbps
- NFR-SEC-01 ข้อมูลผลการศึกษาและไฟล์แนบรับส่งด้วย TLS 1.2 ขึ้นไปเท่านั้น
- NFR-SEC-02 นักศึกษาเรียกดูหรือแก้ไขข้อมูลของนักศึกษาคนอื่นไม่ได้ ต้องได้ HTTP 403
- NFR-SEC-03 การเรียก storage path ของ Transcript โดยตรงโดยไม่มี signed URL ต้องได้ HTTP 401 หรือ 403
- NFR-REL-01 อีเมลที่ส่งไม่สำเร็จต้องถูกส่งซ้ำภายใน 5 นาที และสูงสุด 3 ครั้ง
- NFR-USE-01 นักศึกษาที่ใช้ครั้งแรกกรอกและส่งข้อมูลสำเร็จภายใน 5 นาที โดยผู้ทดสอบ 8 ใน 10 คนทำสำเร็จโดยไม่ต้องขอความช่วยเหลือ

## Acceptance Criteria
- [ ] AC-EDU-01 (FR-EDU-08)
      Given นักศึกษาเข้าสู่ระบบแล้ว รอบเปิดอยู่ กรอกฟิลด์ตาม DR-EDU-01 ครบถูกต้อง และแนบ Transcript 1 ไฟล์
      When  กดส่งข้อมูล
      Then  ระบบบันทึกสำเร็จ สถานะเป็น "รอตรวจสอบคุณสมบัติ" และแสดงข้อความยืนยันพร้อมวันเวลาที่บันทึก
- [ ] AC-EDU-02 (FR-EDU-05)
      Given เว้นว่างฟิลด์ GPAX และ ภาคเรียน
      When  กดส่งข้อมูล
      Then  ระบบไม่สร้างข้อมูล และแสดงข้อความผิดพลาดที่ทั้ง 2 ช่องนั้น
- [ ] AC-EDU-03 (FR-EDU-06, DR-EDU-02)
      Given กรอก GPAX = 4.50
      When  กดส่งข้อมูล
      Then  ระบบไม่สร้างข้อมูล และแจ้งว่า GPAX ต้องอยู่ระหว่าง 0.00-4.00
- [ ] AC-EDU-04 (FR-EDU-07, DR-EDU-06)
      Given แนบไฟล์ .exe ขนาด 1 MB
      When  อัปโหลด
      Then  ระบบปฏิเสธไฟล์ แจ้งชนิดไฟล์ที่รับได้ และข้อมูลที่กรอกไว้ยังอยู่ครบ
- [ ] AC-EDU-05 (FR-EDU-11, FR-EDU-14)
      Given ฐานข้อมูลไม่พร้อมใช้งานขณะบันทึก และไฟล์ถูกอัปโหลดขึ้น Supabase Storage แล้ว
      When  กดส่งข้อมูล
      Then  ไม่มีแถวข้อมูลผลการศึกษาถูกสร้าง ไฟล์ที่เพิ่งอัปโหลดถูกลบออกจาก bucket และหน้าจอแสดงรหัสข้อผิดพลาดพร้อมปุ่ม "ลองใหม่"
- [ ] AC-EDU-06 (FR-EDU-09, FR-EDU-10, NFR-REL-01)
      Given บริการอีเมลไม่ตอบสนอง
      When  บันทึกข้อมูลสำเร็จ
      Then  ข้อมูลยังคงถูกบันทึก มีการแจ้งเตือนในระบบ และมีรายการในคิวส่งซ้ำที่กำหนดส่งภายใน 5 นาที
- [ ] AC-EDU-07 (FR-EDU-02, IF-FORM-01)
      Given รอบแบบฟอร์มมีสถานะ closed
      When  เปิดหน้าฟอร์มและพยายามส่งข้อมูล
      Then  ฟอร์มแสดงแบบอ่านอย่างเดียว และ API ตอบ HTTP 409 โดยไม่แก้ไขข้อมูลใด
- [ ] AC-EDU-08 (FR-EDU-12, CON-DATA-01)
      Given นักศึกษามีข้อมูลของรอบเดียวกันอยู่แล้ว
      When  ส่งข้อมูลอีกครั้ง
      Then  ข้อมูลเดิมถูกอัปเดต และจำนวนแถวของ student_id + round_id นั้นยังเท่ากับ 1
- [ ] AC-EDU-09 (NFR-SEC-02)
      Given นักศึกษา A เรียก API ข้อมูลผลการศึกษาของนักศึกษา B
      When  ส่ง request ด้วย session ของ A
      Then  ระบบตอบ HTTP 403 และไม่คืนข้อมูลของ B
- [ ] AC-EDU-10 (DOM-PDPA-01, DOM-PDPA-02)
      Given มีการบันทึกหรือเปิดดูข้อมูลผลการศึกษา 1 ครั้ง
      When  การกระทำเสร็จสิ้น
      Then  มี audit log 1 รายการที่ระบุผู้กระทำ เวลา รหัสนักศึกษา และชนิดการกระทำ
- [ ] AC-EDU-11 (NFR-PERF-01)
      Given ผู้ใช้พร้อมกัน 300 คน
      When  กดส่งข้อมูลผลการศึกษา
      Then  p95 ของเวลาตอบสนอง <= 2 วินาที
- [ ] AC-EDU-12 (FR-EDU-01, FR-EDU-04)
      Given เปิดหน้าแบบฟอร์มขณะรอบเปิดอยู่
      When  กรอกครบและกดถัดไป
      Then  ฟิลด์บังคับทุกช่องมีเครื่องหมาย * และหน้าสรุปแสดงค่าที่กรอกกับรายชื่อไฟล์แนบครบตรงกัน
- [ ] AC-EDU-13 (FR-EDU-13, DR-EDU-07)
      Given กรอกข้อมูลครบทุกช่อง แต่ไม่แนบไฟล์ Transcript
      When  กดส่งข้อมูล
      Then  ระบบไม่สร้างข้อมูล และแจ้งว่าต้องแนบ Transcript อย่างน้อย 1 ไฟล์
- [ ] AC-EDU-14 (IF-FILE-01, IF-FILE-02, NFR-SEC-03)
      Given มี Transcript ที่บันทึกไว้ใน Supabase Storage แล้ว
      When  เรียก storage path ของไฟล์นั้นโดยตรงโดยไม่มี signed URL
      Then  ระบบตอบ HTTP 401 หรือ 403 และไม่คืนไฟล์

## Assumptions & Open Questions
- ASM-EDU-01 รายการฟิลด์ใน DR-EDU-01 มาจากข้อมูลที่ใช้ตรวจสอบคุณสมบัติ รอยืนยันจากเจ้าของงาน
- ASM-EDU-02 ข้อมูลรอบแบบฟอร์ม (เปิด/ปิด, round_id) มีอยู่แล้วและอ่านได้จากระบบ
- ASM-EDU-03 UC-01 ระบุ NFR เป็น "-" ค่าทั้งหมดในหัวข้อ Quality Requirements จึงเป็นค่าที่เสนอไว้เพื่อให้ทดสอบได้
- ASM-EDU-04 UC-01 ขั้น 4 เขียนว่า "แนบเอกสารที่เกี่ยวข้อง (ถ้ามี)" แต่เจ้าของงานสั่งเมื่อ 2569-09-09 ให้บังคับแนบ Transcript spec นี้จึงยึดตาม DR-EDU-07 และต้องแก้ UC-01 ให้ตรงกัน
- ASM-EDU-05 ระบบใช้ Supabase เป็นทั้งฐานข้อมูลและที่เก็บไฟล์ การ rollback จึงต้องลบไฟล์เองตาม FR-EDU-14 เพราะ storage ไม่ร่วมธุรกรรมกับฐานข้อมูล
- ASM-EDU-06 นักศึกษาสามารถแก้ไขข้อมูลผลการศึกษาได้จนถึงวันสุดท้ายของการส่งเอกสารของรอบนั้น หากเลยกำหนดส่งแล้วระบบจะปิดการแก้ไขอัตโนมัติ
- ASM-EDU-07 คำว่า "นักศึกษา" เป็นคำทางการในระบบและเอกสารทั้งหมด
- ASM-EDU-08 มีเพียง Transcript เป็นเอกสารที่บังคับแนบในฟอร์ม และเอกสารประเภทอื่นเป็นทางเลือกเสริมเท่านั้น
- ASM-EDU-09 ระบบไม่รองรับฟังก์ชันบันทึกร่าง (draft) ก่อนส่งจริง และนักศึกษาจะส่งข้อมูลได้ครั้งเดียวต่อรอบการสมัคร
